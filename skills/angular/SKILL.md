# Angular Skill


Prefer current Angular patterns supported by the project's installed version.

Review:
- standalone architecture where supported/appropriate
- feature boundaries
- smart/presentational separation
- state ownership
- signals/reactivity where appropriate
- RxJS lifecycle correctness
- change detection implications
- lazy loading
- route guards
- HTTP interceptors
- error handling
- accessibility
- testability
- bundle/performance impact

Do not introduce a pattern solely because it is fashionable; follow project/version constraints.
